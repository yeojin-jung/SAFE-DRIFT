# SAFE-DRIFT

SAFE-DRIFT is a data-selection pipeline for fine-tuning language models on a
target task while controlling behavior on off-target reference data.

The repository is organized around three experiment settings. Each setting uses
the same selector and LoRA SFT pipeline, and varies only the candidate pool,
target dataset, reference dataset, evaluator, and model variants.

## Repository Layout

```text
configs/
  pipeline_defaults.yaml                  # shared experiment grid and hyperparameters
  defaults.yaml                           # flat defaults for the low-level runner
  experiments/
    setting_1_code_humaneval.yaml
    setting_2_medqa_medmcqa.yaml
    setting_3_empathetic_esconv_gsm8k.yaml

data/
  setting_1_code/
    codealpaca.jsonl
    humaneval.jsonl
  setting_2_medical/
    prepared/                             # generated by scripts/data/prepare_medical_data.py
  setting_3_empathetic/
    prepared/                             # generated by scripts/data/prepare_empathetic_data.py

scripts/
  run_experiment_pipeline.py              # high-level entrypoint
  run_selector_sft_sweep_code.py          # selector + SFT sweep runner
  data/
    prepare_medical_data.py
    prepare_empathetic_data.py

src/
  baseline_selectors/
  safe_drift/
  evaluation/
  utils/
```

## Experiment Settings

| Setting | Candidate pool | Target | Reference / OOD | Target evaluator |
|---|---|---|---|---|
| 1 | CodeAlpaca | HumanEval | StereoSet | HumanEval pass@1 |
| 2 | MedMCQA | MedQA | TruthfulQA + BBQ, plus MCQ OOD | MedQA MCQ accuracy |
| 3 | Empathetic Dialogues | ESConv | GSM8K | ESConv overlap metrics |
| 4 | FLAN-v2 | IFEval | MMLU | IFEval strict/loose instruction-following |

The setting configs are:

```text
configs/experiments/setting_1_code_humaneval.yaml
configs/experiments/setting_2_medqa_medmcqa.yaml
configs/experiments/setting_3_empathetic_esconv_gsm8k.yaml
configs/experiments/setting_4_flan_ifeval_mmlu.yaml
```

## Shared Defaults

Shared pipeline defaults live in `configs/pipeline_defaults.yaml`.

Important defaults:

```yaml
subset_percentages: [5.0, 15.0]

splits:
  candidate_adam_warmup: 0.03
  candidate_selection: 0.97
  target: [0.34, 0.33, 0.33]
  reference: [0.5, 0.5]

selection:
  selector_feature_method: low_rank
  selector_preconditioner: adam
  max_seq_len: 1024
  low_rank_candidate_max_examples: 5000
  low_rank_candidate_projection_chunk_rows: 256
  reference_fisher_max_examples: 1024
  validation_gradient_max_examples: 256

safe:
  epsilon: 1.0
  rho_values: [0.1, 0.3, 1.0, 3.0]

training:
  train_max_seq_length: 1024
  learning_rate: 2.0e-4
  gradient_accumulation_steps: 16
  num_train_epochs: 1.0
  eval_steps: 20

evaluation:
  generation_max_new_tokens: 128
```

The rank grid is:

```text
KR1024_KT256
KR512_KT128
auto
```

The baseline selectors are:

```text
full, random, dsir, less, prismatic
```

SAFE is run with each `rho` value in `safe.rho_values`.

## What Each Run Does

For each expanded command, `scripts/run_selector_sft_sweep_code.py`:

1. Loads the setting candidate file.
2. Holds out `3%` of candidates for Adam preconditioner warmup.
3. Uses the remaining `97%` as the selection candidate pool.
4. Splits the target file into selector-target, validation, and final-test
   splits using `34/33/33`.
5. Splits reference data into reference-Fisher and held-out reference-eval
   splits using `50/50`.
6. Computes selector features with the low-rank reference Fisher geometry.
7. Runs baseline selectors and SAFE-DRIFT.
8. Fine-tunes a LoRA adapter on each selected subset.
9. Writes metrics, summaries, selected subsets, feature caches, and adapters.

The current low-rank feature setup estimates the low-rank candidate basis from
at most `5000` post-warmup candidates. All post-warmup candidates are still
projected into the learned basis before selection.

## Evaluation

Setting 1:

```text
target validation/test: HumanEval pass@1
reference eval: held-out StereoSet bias metrics
```

Setting 2:

```text
target validation/test: MedQA MCQ accuracy
reference eval: held-out BBQ+TruthfulQA supervised loss
OOD eval: mcq_ood_eval.jsonl with MedQA-style MCQ accuracy
```

Setting 3:

```text
target validation/test: ESConv exact match, token F1, ROUGE-L F1
reference eval: GSM8K numeric accuracy
```

Training metrics are written to `metrics.jsonl`. Final metrics are written to
`summary.json`.

When `compute_entanglement_metrics: true` is set, each selector run also writes
reference/task entanglement diagnostics for its selected subset. These metrics
summarize reference-subspace energy, preconditioner-weighted reference share,
reference load, influence block decomposition, and target/reference alignment.
SAFE runs also report `safe_constraint_report` in the sweep manifest, including
the alpha case and whether the continuous update and selected subset satisfy
the rho/reference and epsilon/norm budgets.
